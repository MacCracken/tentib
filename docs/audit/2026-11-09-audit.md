# tentib Audit Report — 2026-11-09

**Scope:** a P(-1) hardening, optimization and repair sweep (first-party
standards, *P(-1): Hardening*) over the whole repository outside vendored
`lib/`: `src/` (library modules and the demo), `tests/` (suite, bench, fuzz),
`programs/`, `examples/`, CI and release workflows, and the documents.
**Baseline:** 1.1.1 (commit `fa88d3a`, cyrius 6.7.18, tyche 1.2.2, rosnet 1.4.1,
akshara 1.1.2). **Result:** 1.1.2. The second tentib audit; the first is
[`2026-07-06-audit.md`](2026-07-06-audit.md) (0.8.0).

## Executive summary

Two MEDIUM defects. **`tx_bwd` wrote past the heap for an out-of-range token
id**: the embedding-gradient scatter adds row `tokens[t]` of `tx_dtokemb`, so a
token ≥ V (or < 0) added C f64s into whatever followed the buffer. The three
whole-model forwards read past the embedding table the same way. Token ids are
data, from a tokenized corpus or, on the serving path, from a consumer's
tokenizer, and nothing checked them. **`bl_ste_mask_x` zeroed the gradient of
each token row's max-magnitude activation in about 14% of rows**: it masked
where `|x/s| > 127`, and at the row max `a/(a/127)` rounds to
`127.00000000000001` for 13.65% of absmax values (a = 1.1, 2.2, 0.01, …) while
the forward never clamps that element.

The LOW findings are the rest of the input surface (target ids, dims checked
against nothing, a NaN laundered into a finite logit by the integer path), the
guard's reporting channel, test gaps (the activation STE's `dx`, the GPU tile
fallback and every guard's fail path were never tested; the fuzz harness was a
no-op), CI integrity, and documentation that had drifted from the code
(including a wrong i32 bound in the SIMD kernel's comment).

Speed, every change bit-identical (a 333,281-value golden dump): the f64 forward
−33%, the integer-SIMD whole-model mode −42%, one-time packing −53%, per-token
activation quant −35%, packed serving −6% (13.3k → 14.2k tok/s), a training step
−19%. One hardening check, measured at 4–10% of the SIMD kernel, was not adopted.

## Method

- **Toolchain sweeps (6.7.18):** `cyrius vet` (9 deps, 0 untrusted), `cyrius
  deny` (0 violations), `cyrius doc --check` (67 undocumented fns → 0),
  `cyrius coverage --exec` (the only library fn no corpus run entered:
  `ternary_matmul_free_gpu`), `cyrius lint` (53 warnings → 0, every shipped
  source), `cyrius fmt --check`, `cyrius audit` (exit 1 → exit 0),
  `cyrius deps --verify` / `--locked`.
- **Manual review** of every line of `src/`, `tests/`, `programs/`,
  `examples/` and both workflows, with each suspicion checked by experiment
  before it was accepted.
- **Numerical experiments** (IEEE doubles, Python as the oracle): the mask
  boundary over 2M random absmax values (13.65% affected); integer order of
  `f64_abs` bit patterns vs `f64_gt` over 200,005 non-negative pairs incl.
  zero, subnormals and +Inf (0 mismatches; NaN's bits sort above +Inf).
- **iv_dp8 lowering read in the cyrius source** (`src/backend/x86/float.cyr`,
  `src/backend/aarch64/emit.cyr`): both targets fold the four i32 lanes **in
  i32** before sign-extending, which fixes the exactness bound (finding 12).
- **Golden dump:** raw bit patterns of every public function's outputs at fixed
  seeds — the four integer kernels at eight shapes (K across every `K % 16`
  split, ragged against the GPU tile), BitLinear forward/backward, the layers,
  softmax-CE, `lm_train`, the bite-F corpus run, and three trained whole models
  (one at C = 32 / F = 128 so the SIMD span is exercised whole-model) through
  every inference mode, packing, and one full gradient: **333,281 values in 21
  sections**. Deterministic on re-run. 1.1.1 vs 1.1.2: **exactly one value
  differs**, inside the section tagged for the mask fix (a max-element `dx`, 0
  before, −0.894 after). Every optimization and refactor was checked against it
  before it was kept.
- **Cross-target:** the suite (139/139), the fuzz harness (5,000 rounds) and the
  demo run on aarch64 under `qemu-aarch64`, where `f64_to(NaN)` is 0 rather than
  INT_MIN and rosnet's f64 multiply-add is fused.
- **Mutation testing:** nine injected defects. The suite killed 9/9; the fuzz
  harness killed the 7 that change outputs. The two it misses (guard disabled,
  guard widened) are by design the fork harness's to catch.

  | mutant | suite | fuzz |
  |---|---|---|
  | SIMD tail: the −1 byte tested as 254 | killed (6) | P1 |
  | `wsum` summed over all K, not K16 | killed (1) | P1 |
  | mask threshold back to 127 | killed (2) | P7 |
  | NaN fix reverted (`f64_gt` absmax) | killed (2) | P6 |
  | token-id guard disabled | killed (3) | — |
  | GPU fallback drops one k per tile | killed (4) | P1 |
  | `Weff` table sign flip | killed (10) | P4 |
  | a per-row code check that admits 128 (later dropped, see P5 below) | killed (1) | — |
  | weight clip widened to ±2 | killed (5) | P4 |

- **Benchmarks:** `scripts/bench-history.sh` (new) before and after, one
  session, one binary per run, pinned to core 4, median of three runs; 24 rows
  each in `bench-history.csv`. A training-step row was added to the harness
  before the baseline was taken.

## Findings

### MEDIUM — fixed

| # | Finding | Where | Fix |
|---|---|---|---|
| 1 | **Out-of-range token ids corrupted the heap.** `tx_bwd`'s embedding scatter `t_add_into(tx_dtokemb + tok * C8, …)` wrote C f64s past (or before) the buffer for `tok ≥ V` or `tok < 0`; `tx_fwd`, `tx_fwd_q` and `tx_fwd_packed` read past `tx_tokemb` for the same ids. Ids come from a tokenized corpus or, when serving, a consumer's tokenizer; a vocabulary mismatch is enough. | `src/block.cyr`, `src/kernel.cyr` | `_ids_in_range` (O(T), once per call) in one shared embed, `_tx_embed`, used by all three forwards; `tx_bwd` checks again before its scatter. Fails loud. |
| 2 | **`bl_ste_mask_x` zeroed the max element's gradient in ~14% of rows.** It masked where `\|x/s\| > 127`; at the row max `a/(a/127)` rounds above 127 for 13.65% of absmax values, while the forward's `round(a·127/a)` is exactly 127 and never clamps. The comment called the boundary measure-zero. The suite called the mask but never asserted its `dx`. | `src/bitlinear.cyr` | Saturated means the forward's clamp changed the code: `\|x/s\| ≥ 127.5` (exact under round-half-away and round-half-even). With `bl_act_quant`'s scale the mask is now the identity, as documented; it still bites for a smaller caller scale. Regression tests at a = 1.1 and at 200 / 127.4 / 127.5. |

### Performance — bit-identical

Same session, one binary per run, core 4, median of three (`bench-history.csv`):

| # | Change | Before → after |
|---|---|---|
| P1 | `bl_weight_effective`: `ternary_one` inlined (its per-weight γ = 0 test is dead on that branch) and `Weff` read from a 3-entry table of the precomputed products `{−γ, 0·γ, +γ}` — the same `f64_mul` once instead of per weight. Every training forward and every re-quantizing inference mode runs it over every weight. | f64 forward 11.16 → 7.44 ms (−33%) |
| P2 | `tsimd_pack_w` walks `Wq` row-major (sequential 8-byte reads; the strided side is the small byte writes) with one ternary check per row; `wsum`'s integer sums do not depend on order. | 4.82 → 3.28 ms (−32%); `tx_pack` 8.28 → 3.93 ms (−53%, with P1); mode 2 10.84 → 6.30 ms (−42%) |
| P3 | `act_quant_int`: the integer-order absmax (finding 5) and per-row base pointers. | 6.81 → 4.41 µs (−35%); packed serving 2.40 → 2.25 ms (−6%, 13.3k → 14.2k tok/s) |
| P4 | The six bias-free projections pass `db = 0` to `linear_bwd` (rosnet skips the pass) instead of accumulating into scratch nothing read (`blk_db` / `mlp_db`, removed); `bl_ste_mask_w` loads directly. | training step 27.85 → 22.43 ms (−19%, with P1) |

The per-layer kernel rows are unchanged (within ±3%): the kernels themselves
were not touched. Because P1 also speeds the f64 reference path, the
packed-vs-f64 ratio at the bench config falls from 4.2× to 3.3× even though
serving got faster; the integer-SIMD whole-model mode is now 1.2× the f64 path
(was 1.0×).

### Measured, not adopted

- **A per-row activation-code check in `ternary_matmul_free_simd`** (one AND + OR
  per element on the offset it already computes, guarding the u8 wrap at code
  128): 4–10% of the kernel at M = 1 in alternating A/B runs (1,870 → 2,009 ns
  at 128², 4,651 → 5,110 ns at 256², 29,146 → 30,357 ns at 768²). Hot loops carry
  no checks (the 0.8.0 posture), every in-repo caller passes `act_quant_int`'s
  codes (fuzz property P2), and the contract — codes in [−128, +127] — is now
  stated precisely in the source and `api.md`.

## Observations — not changed, and why

- **Re-calling an `*_init` allocates fresh buffers** (the bump allocator never
  frees). Documented contract (`api.md`, "Allocation & lifetime"); `tx_train`
  calls `tx_init`, so a long-lived consumer should call the trainers a bounded
  number of times.
- **`bl_ste_mask_w` divides once per weight** in every backward. The forward
  computes the same `W/γ`, but there is nowhere to keep it without changing a
  frozen signature, and testing `|W| < γ` instead changes bits at the boundary.
- **The GPU tile path on AGNOS is untested here** (no gfx90c); its host fallback
  is now gated at ragged shapes. `#82`'s i32 product is mod 2³², exact only for
  int8-range codes and ternary weights — the documented contract.
- **akshara 1.1.2 still pins rosnet 1.2.2**; tentib's root pin (1.4.1) wins.
  akshara calls only `t_alloc` / `t_zero`; rosnet's API is unchanged.
- **The "vs f64" figures in `docs/benchmarks.md`, the README and `api.md`** are
  the 2026-07-06 run of record. The 1.1.1 note records rosnet's faster f64 path;
  1.1.2's numbers are in the CHANGELOG and `bench-history.csv`. A full
  re-baseline remains open (maintainer's call).
- **No bounds checks on caller buffers** — unchanged and still deliberate: the
  1.1.2 guards are on data (ids) and on tentib's own init-owned state (dims vs
  sizing), never on element accessors or inside kernel loops.

## Downstream

No public signature changed. On valid input every output is bit-identical to
1.1.1 except `bl_ste_mask_x`'s, which no longer zeroes the max element's
gradient. Inputs that used to corrupt memory or return wrong numbers now fail
loud (exit 1, message on stderr): out-of-range token or target ids, dims other
than the init dims or past their sizing, and calls before the matching init. A
NaN activation now gives NaN outputs for its row on the integer paths.
`absmean(·, 0)` returns 0. A consumer no longer needs to define `puts` for
tentib (akshara's four hooks remain). Consumers' suites were not re-run (none
pins tentib yet).

# Getting started with tentib

## Build

```sh
cyrius deps                              # resolve dependencies
cyrius build src/main.cyr build/tentib    # compile
cyrius test                              # run [build].test + tests/*.tcyr
```

## Layout

- `src/main.cyr` — entry point. Top-level `var r = main(); syscall(SYS_EXIT, r);`.
- `src/test.cyr` — top-level test entry referenced by `cyrius.cyml [build].test`. Add unit cases here or in `tests/tentib.tcyr`.
- `tests/tentib.tcyr` — primary test suite (`cyrius test` auto-discovers).
- `tests/tentib.bcyr` — benchmarks (`cyrius bench`).
- `tests/tentib.fcyr` — fuzz harness (`cyrius fuzz`).
- `dist/tentib.cyr` (+ `dist/tentib-gpu.cyr`) — the library bundle consumers import,
  regenerated by `cyrius distlib --all`. To depend on tentib from another program, see
  [`consuming-tentib.md`](consuming-tentib.md).

## Adding a feature

1. Edit `src/main.cyr` (or add a new module and `include` it).
2. Add a test case to `tests/tentib.tcyr`.
3. Run `cyrius test`.
4. If you changed a library module, run `cyrius distlib --all` and commit `dist/`.
5. Bump `VERSION` (then `cyrius distlib --all` again, which stamps it into the bundles)
   and add a CHANGELOG entry before tagging.

See [`../adr/template.md`](../adr/template.md) when a non-trivial design choice deserves an ADR.
